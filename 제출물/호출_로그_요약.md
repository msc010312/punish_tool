# 응답 엔진 호출 로그 요약

> 실측 기반. 원자료: [`eval_report.json`](../eval_report.json)(17콜) · [`ttfb_probe.json`](../ttfb_probe.json)(TTFB)

## 엔진 구성

| 항목 | 값 |
|---|---|
| **엔진** | llama.cpp (동봉 `llama-server.exe`, Vulkan) |
| **모델** | Qwen3-8B (Q4_K_M GGUF, ~5.2GB) |
| **API** | OpenAI 호환 `/v1/chat/completions` (127.0.0.1:18321) |
| **실행** | 로컬 · 오프라인 (`llm_server.py`가 자동 기동/관리) |
| **개발 폴백** | Ollama(qwen3:8b) |

## 사용량 / 비용

| 항목 | 값 |
|---|---|
| 평가 호출 수 | 17콜 (+ TTFB 프로브 3콜) |
| **1콜 평균 비용** | **$0 (로컬 추론 — API 과금 없음)** |
| 누적 API 비용 | $0 |
| 전력/하드웨어 | 사용자 GPU (배포 비용 0원이 설계 목표) |

> **비용 0원**이 이 프로젝트의 핵심 설계 결정. 클라우드 LLM API 대신 로컬 GGUF를 동봉해
> 배포·운영 비용을 없앴다(제1원칙과 함께 "무료·오프라인 배포"가 목표).

## 지연 (TTFB / 전체) — ⚠ 최악 조건 측정

> 아래 수치는 **TTS 학습과 GPU를 동시 점유한 상태**에서 측정. 단독 사용 시 대폭 단축.

| 지표 | 값 (동시부하) | 비고 |
|---|---|---|
| TTFB 중앙값 | ~8초 | 첫 가시 토큰까지 (`<think>` 필터 후) |
| TTFB 범위 | 7~85초 | 사고형 모델 — 복잡 질문일수록 추론 길어짐 |
| 전체 응답 평균 | 60.7초 | 스트리밍이라 체감은 TTFB 기준 |
| 전체 응답 중앙값 | ~50초 | |

### 특성
- **스트리밍 출력**: 사용자는 전체 완료를 기다리지 않고 TTFB 시점부터 글자를 본다.
- **사고형 모델 트레이드오프**: qwen3:8b은 `<think>` 추론으로 답 품질을 높이지만 TTFB가 늘어난다.
  코드가 `<think>` 블록을 필터링해 사용자에겐 결론만 보인다.
- **동시부하 왜곡**: 측정 시 llama-server가 학습과 12GB VRAM을 나눠 써 CPU 오프로드가 발생.
  전용 GPU(단독 실행) 환경에선 TTFB 수 초 이내로 예상.

## 로그 파이프라인 (구조)
```
사용자 질문 → _gather_context()         [매치사실 + 로컬KB(coach_kb) + 웹(coach_web)]
            → chat_stream()             [시스템프롬프트 + 근거 + 히스토리 → llama-server]
            → 스트리밍 응답
            → _unverified_numbers()     [사후 숫자 가드 — 근거 밖 수치 경고]
```
호출마다 근거 블록·응답·미검증 수치가 `eval_report.json` 형태로 남아 감사 가능(대화·검색 로그).
