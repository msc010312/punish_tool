# 프로젝트 회고서

> 개인 프로젝트(AI 보조 개발). "협업"은 개발 프로세스·의사결정 관점에서 정리한다.

## 잘된 점 (What went well)

### 1. "측정 우선(실측)" 원칙이 끝까지 버팀목이 됨
"믿기 전에 측정한다"를 규율로 삼았다. 기능마다 실제 수치로 검증하고, 감이 아니라
데이터로 방향을 틀었다. 덕분에 잘못된 길에 오래 머물지 않았다.
- 배너 감지 95%(n=22, 손 카운트), 무브ID 후보들 실측 비교(NCM 42% vs DINOv2 57%)
- 코치 숫자 가드를 결정론적으로 검증(이번 평가 리포트)

### 2. 실패하면 빠르게 피벗
막히는 접근을 붙잡지 않고 갈아탔다.
- 무브ID: CNN(새 영상 81%→0%) → DINOv2 RAG
- 코치: QLoRA v1~v4(자유대화 손상) → 베이스 + 숫자 가드
- 배포: Ollama 의존 → llama.cpp 통짜 동봉

### 3. 제1원칙을 코드로 강제
"잘못된 정보 금지"를 구호가 아니라 **결정론적 숫자 가드**로 보증했다. LLM을 신뢰하지
않고 코드가 마지막에 검증하는 구조가, 소형 로컬 모델에서도 사실성을 지켰다.

### 4. 선행 사례를 실측으로 재현
한국어 TTS는 NDC26(넥슨게임즈) 발표를 근거로 삼되, 자막을 직접 받아 분석하고
웜스타트 91% 전이를 코드로 검증한 뒤 진행했다. "발표대로 될 것"이라 가정하지 않았다.

## 개선점 (What to improve)

### 1. 값비싼 실패 전에 더 일찍 검증했어야
CNN 무브ID에 학습·데이터를 투자한 뒤에야 일반화 실패를 확인했다. 소규모 홀드아웃으로
**먼저** 일반화를 확인했다면 시간을 아꼈다. → 이후 DINOv2는 소량으로 먼저 측정하고 진행.

### 2. 의존성 관리
TTS 학습 환경에서 pyannote 설치가 CUDA torch를 CPU 버전으로 갈아치우는 등
의존성 지옥을 겪었다. 처음부터 **격리된 venv + 버전 고정(requirements 분리)**을
엄격히 했어야 한다. → 사후에 `_run_noworker.py` shim으로 흡수하고 문서화.

### 3. 스코프 관리
영상분석·코치·아바타·음성 4축을 동시에 밀다 보니 각 축의 마무리(예: KO 음성 완성,
립싱크 동기화)가 뒤로 밀렸다. → 축별 "동작 최소본"을 먼저 세우고 깊이를 더하는 순서가 나았다.

### 4. 재현성·로그
학습 중단/재개를 여러 번 하며 로그 append로 인한 혼동, 게임 GPU 경합으로 인한 오진단이
있었다. → 실행마다 새 로그, 체크포인트 정책 명시, 리소스 경합 가정을 먼저 점검하도록 개선.

## 한 줄 교훈
> **측정이 방향을 정한다.** 감으로 깊이 파기 전에 싸게 측정하고, 실패는 빨리 인정하고 피벗한다.
