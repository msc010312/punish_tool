# 프로젝트 설명서 — Punish Tool

## 1. 기획

### 1.1 문제 정의
대전격투 게임(길티기어 스트라이브, GGST)에서 실력 향상의 핵심은 **"상대 기술이 막혔을 때
내가 무엇으로 확정 반격(punish)이 되는가"**를 아는 것이다. 이 정보는 Dustloop 같은 방대한
프레임 데이터표에 흩어져 있어, 초·중급자는 대전 중은커녕 리플레이를 봐도 못 찾는다.

### 1.2 해결 방식
리플레이 영상을 넣으면 **자동으로 그 순간을 찾아 반격 해답을 알려주는** 코치. 여기에
게임 캐릭터 **솔 배드가이**를 AI 휴먼(아바타 + 음성 + 페르소나)으로 세워 "실제로 코치가
말해 주는" 몰입 경험을 얹는다.

### 1.3 페르소나 카드 — 솔 배드가이
| 항목 | 내용 |
|---|---|
| 정체성 | 초공격적 스트라이커, 현상금 사냥꾼 |
| 말투 | 반말, 퉁명·직설, 짧고 굵게, 서론 없음 |
| 원칙 | 잔소리·훈계 금지 / 욕설·비하 금지(퉁명 ≠ 무례) |
| 코칭 톤 | "뭘 하면 이기는지"만 툭 던진다 |

### 1.4 도메인 카드 — GGST
33개 플레이어블 캐릭터, 60fps 기반 프레임 시스템, 가드/카운터/RISC/Guts/Defense 등
데미지 보정 체계. 공식 한글 기술명 33캐릭 매핑 보유(`move_names_ko.json`).

### 1.5 제1원칙 (Non-negotiable)
> **사용자에게 잘못된 정보를 주지 않는다. 애매하면 침묵한다.**
격투게임 코칭에서 틀린 프레임 수치는 나쁜 습관을 심는다. 따라서 시스템 전체가
"측정된 사실만 말하고, 나머지는 모른다고 답한다"를 코드로 보증한다.

## 2. 시스템 아키텍처

측정(사실 추출)과 언어(코칭 표현)를 분리한 파이프라인.

```
게임 영상 ─┬─▶ ① HUD 리더 ──▶ timeline.json ──▶ ② 펀ish 엔진 ─┐
           │   (비전)          (이벤트)          (프레임 계산)  │
           └─▶ ③ 무브ID ───────────────────────────────────────┤
                                                                 ▼
                                          분석 리포트(analyze_match) ──▶ AI 코치(LLM+RAG+가드)
                                                                            │
                                                          ┌─────────────────┼─────────────────┐
                                                        GUI              음성(TTS)          아바타(3D)
```

### 2.1 ① HUD 리더 — `src/hud_reader.py` (1,109줄)
- 60fps 영상을 프레임 단위로 훑어 **체력바 색 자가보정**으로 피격/카운터/펀ish 이벤트를 뽑는다.
- 무브 인식 없이 "언제 누가 데미지를 입었는지"만 확정 → 오검 최소화.
- 배너(캐릭 이름표) 감지율 실측 95%(n=22), 오검 0.

### 2.2 ② 펀ish 엔진 — `src/punish_engine.py` (472줄)
- **프로젝트의 두뇌.** "A가 기술 X를 썼고 가드됐다"만 받으면, 프레임데이터로
  "B는 무엇으로 확정 반격이 되는가"를 즉답.
- 데미지 역산 체인(60fps 플래토 + Defense + Guts + RISC)으로 편향 제거.

### 2.3 ③ 무브ID (세 갈래 접근, 실측 기반 선택)
- `vlm_id.py`(477줄): 로컬 VLM에게 **객관식**으로 질문 → {캐릭, 무브, 상황, 확신도}
- `rag_moveid.py`(244줄): **DINOv2 임베딩 + 최근접검색** (330MB, CPU 가능, 오프라인) — 채택 경로
- `input_moveid.py`(160줄): 리플레이 **입력표시 판독**으로 무브ID 확정 (판독기 검증 완료)
- 결론: CNN 학습은 새 영상 일반화 실패(81%→~0%) → 이미 일반화된 표현(DINOv2 RAG, 57%)으로 전환.

### 2.4 분석 리포트 — `src/analyze_match.py` (701줄)
timeline + 프레임데이터를 묶어 "이 순간 뭘 할 수 있었나"를 자연어로 정리(AI 없이도 동작).

### 2.5 AI 코치 (AI 엔진)
- `coach.py`(362줄): 페르소나·규칙·few-shot·스트리밍. `build_facts()`가 만든 **사실만** LLM에 전달.
- `coach_kb.py`(288줄): **오프라인 RAG** — 번들 JSON에서 관련 프레임·기술·메카닉만 근거 블록으로 추출.
  데이터에 없으면 빈 블록 → LLM은 "모른다"고 답하도록 프롬프트가 강제.
- `coach_web.py`: Dustloop MediaWiki API로 최신 정보(패치노트 등) 온라인 보강(선택).
- **결정론적 숫자 가드**: `_unverified_numbers()` — 근거·질문에 없는 단위 숫자(N프레임/N뎀)를
  후처리 정규식으로 잡아 경고. 코드가 제1원칙을 최종 보증.

### 2.6 백엔드 — `src/llm_server.py` (176줄)
- 앱 폴더의 `llama/llama-server.exe` + `*.gguf`(qwen3:8b Q4_K_M)를 자동 실행.
- OpenAI 호환 API(127.0.0.1) 제공. **Windows Job Object**로 앱 종료 시 고아 프로세스 정리.
- 사용자는 Ollama·터미널을 몰라도 됨(개발 중엔 Ollama 폴백).

### 2.7 클라이언트 — `src/gui.py` (734줄)
PySide6. [탭1 AI 코치] Claude 앱 스타일 채팅(영상 드롭 → 분석 → 코칭), [탭2 분석] AI 없이 직접 보기.

## 3. 멀티모달

### 3.1 비전
- HUD 자가보정(체력바 색), 배너 템플릿 매칭, YOLO pose(`yolo11x-pose.pt`), DINOv2 무브ID.

### 3.2 음성 — Style-Bert-VITS2 한국어 개조
NDC26(넥슨게임즈, 블루아카이브 TTS) 발표 방식을 따라 **한국어 미지원 SBV2를 개조**.
- 언어 의존부는 **G2P·BERT 두 곳뿐** → 한국어 G2P(`nlp/korean/`, g2pkk+mecab-ko) + KLUE-RoBERTa-large(1024) 배선.
- **웜스타트**: JP-Extra 사전학습에서 **91%(66.6M/73.2M) 전이**, 텍스트 인코더(9%)만 재학습.
  음소 심볼을 이름으로 대응시켜 112개 전이 + 13개 신규.
- **JP 솔 파인튜닝 완료**(100 epochs) → 음성 샘플 4종 합성(`tts/samples/sol_jp/`).
- KO 기반모델: AI Hub "감성·발화스타일" 13.2시간/14화자 코퍼스로 웜스타트 학습 → **Epoch 29 도달**(한국어 발음·G2P·억양 검증됨, 샘플 합성). 다음: 한국어 솔 파인튜닝.
- 결정적 도구: `tts_prep.py`(전처리·프로파일), `tts_aihub.py`(AI Hub→코퍼스), `tts_warmstart.py`(가중치 변환), `tts_train.py`(학습 러너), `tts_synth.py`(합성).

### 3.3 아바타 — three.js 실시간 3D
- 게임 3D 모델(FModel 추출) → Blender 본 구동 → GLB → three.js r147 + QWebEngineView.
- ArcSys 툰셰이더(GLSL) 재현, 립싱크·깜빡임·표정·숨쉬기. 코치 답변 길이에 맞춰 말하기 홀드.

## 5. 실행 방법

### 5.1 배포본 (권장, 설치 불필요)
```
dist/FrameAnalyzer/프레임분석기_실행.bat  더블클릭
```

### 5.2 개발 환경
```bash
py -3.11 -m pip install -r requirements.txt   # PySide6, opencv, torch(CUDA) 등
py -3.11 src/gui.py                            # GUI 실행
```

### 5.3 TTS 학습 (참고)
```bash
py -3.11 src/tts_aihub.py --hours 14 --per-style 2   # AI Hub → 코퍼스
py -3.11 src/tts_warmstart.py                        # JP-Extra → KO 웜스타트
bash src/ko_base_train.sh                             # KO 기반모델 학습(중단/재개 가능)
py -3.11 src/tts_synth.py --model-dir Data/SOL_JP --lang JP --texts "..." --out-dir tts/samples/sol_jp
```

## 6. 실험·의사결정 로그 (요약)

- **무브ID**: 모션·오디오·CNN 학습 전부 실측 벽 → appearance NCM 42%/60%(top3), DINOv2 RAG 채택.
- **코치 파인튜닝**: v1~v4 QLoRA 전부 자유대화 손상 → **베이스 qwen3:8b + 숫자 가드**로 결론
  (코드가 제1원칙을 보증, 학습으로 페르소나만 흉내내다 사실성 잃는 것 방지).
- **TTS**: SBV2 한국어 개조가 처음부터 막힘(upstream 미지원) → NDC26 방식 + 웜스타트로 돌파.
- **배포**: Ollama 의존 제거 → llama.cpp 통짜 동봉(설치·터미널 없이 실행).
