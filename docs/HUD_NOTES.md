# GGST HUD 레퍼런스 (검출 기준표)

길티기어 스트라이브 표준 HUD / 1080p~1440p / 기본 비율 기준.
좌표는 화면 비율(0~1). 정확한 HP바 박스는 `hud_config.json`(사용자 캘리브레이션)에 저장.
색은 BGR(OpenCV 순서).

## 1. 체력바 (HP bar) — 구현됨
- 위치: 상단. P1 좌측 / P2 우측. (정확값은 hud_config.json)
- **두 가지 fill 상태** (둘 다 '남은 체력'으로 인정해야 함):
  - 평상시(30% 초과): **크림색** ≈ BGR(130,180,255) = R255/G180/B130
  - **30% 이하: 주황색 경고** ≈ BGR(40,110,170) = R170/G110/B40
- 잃은 체력 trail: 어두운 빨강 ≈ R130/G20 (G가 낮아 fill과 구분됨)
- 감소 방향: **바깥(포트레이트)쪽부터 닳고 fill이 안쪽(중앙)에 남음** → fill 폭 / 최대폭 = HP%
- 코드: `hud_reader.cream_mask()` (크림 OR 주황)

## 2. COUNTER 텍스트 + 카운터 레벨 — 검출 대상(핵심)
- 위치: **체력바 약간 아래, 양쪽 바깥쪽**.
  - 좌측 ≈ x 0.03–0.22, y 0.19–0.33
  - 우측 ≈ 좌우대칭 (x ~0.78–0.97)
- 색: **밝은 노랑** ≈ BGR(96,198,246) = R246/G198/B96. PUNISH 텍스트도 **같은 색**(구분 불가).

### GGST 카운터 레벨 시스템 (텍스트 '크기'가 핵심 신호)
출처: dcinside 길티기어갤 #372933. 카운터 히트는 4단계:
| 레벨 | 프레임 이득 | 텍스트 | 적용 기술 |
|---|---|---|---|
| 베리스몰 | 0 | 없음 | 장풍 |
| 스몰 | **+6** | **없음** | 5P·2P·5K·2K 등 짧은 기본기 |
| 미디움 | **+13** | COUNTER (작게, 화면 한쪽) | 히트스탑 추가 |
| 라지 | **+18** | COUNTER (크게, 화면 중앙 가로지름) | H기·큰 동작 |

함의(도구 설계):
- 검출기는 **미디움·라지만 잡는 게 정상** (베리스몰·스몰은 텍스트 자체가 없음).
- 크기 임계는 **오검출(작은 불꽃 노이즈) 제거**에 유효.

### COUNTER vs PUNISH — 글자로 구분해야 함 (위치/색/크기로는 불가)
타이밍 의미 (게임 로직):
- **PUNISH**: 상대 기술의 **회수프레임(recovery, 후딜)** 에 맞힘 = '확정 반격 성공'. 사용자 목표 핵심 신호.
- **COUNTER**: 상대 기술의 **시작(startup)·발동(active)** 에 맞힘.
- **예외**: 각성필살기 / 잡기 / 승룡류(623S, 볼캐닉바이퍼 등)는 **후딜에 맞아도 COUNTER**.

화면 표시:
- **LARGE 카운터**: 화면 **중앙**에 매우 크게. (별개 축 — 사이드 영역엔 일부만 번짐)
- 사이드(맞은/막은 쪽)에 뜨는 노랑 텍스트는 **3종**: COUNTER / PUNISH / **JUST(직전가드)**.
  같은 색·폰트·위치 → **글자(OCR)로만 구분**. 색/크기 불충분.
- OCR: tesseract 설치됨(`C:/Program Files/Tesseract-OCR/tesseract.exe`).
  노랑 마스크→이진화→OCR→{COUNTER,PUNISH,JUST} 퍼지매칭. 깨끗한 배경(회색돌)이면 잘 읽힘,
  불·캐릭터 겹친 프레임은 실패할 수 있어 'unknown' 폴백.
- '놓친 확정 반격' 코칭은 텍스트가 아니라 프레임 DB(②엔진)로 계산.

## 6. 방어 시스템 (출처: dcinside 길겔 #246191)
- **직전가드(Just Defense)**: 가드 시작 2F 내 피격 시 성공 → **'JUST' 텍스트 + 흰 이펙트**.
  - 이점: 가드뎀X, 넉백X, 텐션 2배, 공중 직가는 착지경직 19F→5F.
  - 실패 시 5F 재가드 불가.
  - **직가 성공하면 거리가 가깝게 유지 → 퍼니쉬가 더 쉬움.**
- **폴트리스 디펜스(FD)**: 텐션 소모. 가드뎀X·리스크X, 상대를 밀어냄. 직전FD는 상대 넉백 큼.
- **PUNISH 정의(확정)**: 상대 공격의 **액티브가 끝난 뒤(회수프레임)** 히트 시 표시.
  - 예외: 각성필살기/잡기/승룡류(623S, 볼캐닉바이퍼)는 회수에 맞아도 COUNTER.
- 가드경직 중엔 가드/사이크버스트/황로망캔슬만 가능.

## 3. 콤보 카운터 (Combo count) — 검출 대상
- 위치: **콤보하는 쪽**에 큰 스타일 숫자 + 영문 단어("eight" + 거대한 "8").
  - 좌측 콤보 ≈ x 0.05–0.30, y 0.25–0.55 (우측은 대칭)
- 숫자가 떠 있으면 = 히트 콤보 진행 중. 정확한 숫자 읽기는 OCR/템플릿 필요.

## 4. 버스트 게이지 (Burst) — 색으로 잔량 판별
- 위치: 체력바 아래 중앙쪽(좌우 각 플레이어).
- **색 = 잔량 단계**:
  - 100%: **파란색**
  - 50–99%: **연두색**
  - 0–49%: **올리브색**

## 5. 텐션 게이지 (Tension) — 하단, 기어 점화로 단계 판별
- 위치: 화면 **하단** 좌우 노란 바.
- **기어 점화 = 단계 신호**:
  - 50%: 기어 **1개** 점화
  - 100%: 기어 **2개** 점화

## 기타 화면 텍스트
- 라운드 타이머: 중앙 상단 큰 숫자.
- "Rollback frames / ms": 온라인 매치 상단(분석엔 무관, 무시).
- 라운드 승패 표식: 중앙 상단 양옆.

## 거리(reach) 2차 필터 — 현재 막힌 부분
"가드백/거리 때문에 안 닿는 기술 제외"는 두 데이터가 있어야 작동하는데 둘 다 없음:
1. **캐릭터 x좌표 검출** — 스크롤·불 배경 위 캐릭터 추적은 불안정(미구현).
2. **기술별 리치 데이터** — 현재 Dustloop Cargo 스크랩(MoveData_GGST)에 reach/range 필드 없음.
   → 다른 소스/수동 입력 필요.
- 엔진엔 훅만 준비됨: `Move.reach`(=None) + `find_punishers(distance=...)`.
  두 데이터가 채워지면 즉시 작동(코드 수정 불필요).
- 당장은 카운터/펀ish '직후' 후속기는 대개 근접(방금 맞힘)이라 거리 필터 가치가 낮음.

## 입력 영상 주의
- 이 DVR 녹화는 **가변 프레임**이라 cv2 seek가 부정확 → 시각 기반 표시 시
  먼저 `ffmpeg -vsync cfr -r 60` 으로 CFR 변환 권장. (순차 스캔 측정은 정확)
